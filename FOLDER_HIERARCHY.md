## 📋 Navigation Guide

### To Add a New Screen
1. Create feature folder in `lib/presentation/screens/`
2. Add screen file: `{feature}_screen.dart`
3. Create provider if needed: `lib/presentation/providers/{feature}_provider.dart`

### To Add a New Service
1. Create service file in appropriate `lib/services/{category}/`
2. Implement singleton pattern or Riverpod provider
3. Expose via provider in `lib/presentation/providers/`

### To Add a New Data Model
1. Create request model: `lib/data/models/requests/{name}_request.dart`
2. Create response model: `lib/data/models/responses/{name}_response.dart`

### To Add Documentation
1. Place in appropriate `docs/` subdirectory
2. Link to main documentation index
3. Update this hierarchy guide

## 🎯 Best Practices

### Naming Conventions
- **Screens**: `{feature}_screen.dart` (e.g., `login_screen.dart`)
- **Providers**: `{feature}_provider.dart` (e.g., `auth_provider.dart`)
- **Repositories**: `{feature}_repository_impl.dart`
- **Services**: `{feature}_service.dart`
- **Models**: `{feature}_model.dart`

### Import Organization
1. Dart imports
2. Flutter imports
3. Package imports
4. Relative imports

### Test Organization
- Unit tests: `test/unit/`
- Widget tests: `test/widget/`
- Integration tests: `test/integration/`
